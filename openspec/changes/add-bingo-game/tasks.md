## 5. Playing the game

- [x] 5.1 Implement the version-checked state update helper from design.md decision 5 (atomic, `settle` first, `update(... version=v+1)` filtered on the old version, one retry) and use it in `POST /bingo/r/<code>/draw/` with `seen`. Add tests: a draw adds a new, unrepeated ball; the first draw moves `waiting` to `linea`; a repeated request with the same `seen` draws only one ball; no draw during a pause, after the game has finished, or once 90 balls are drawn (with the Spanish "no quedan bolas" message). Verify `manage.py test bingo` passes.
- [x] 5.2 Implement `POST /bingo/r/<code>/mark/` (`{number, marked}`, idempotent, own card only, refused once the game has finished). Add tests: marking a drawn or undrawn number persists across reloads, unmarking works, a number not on the card is refused, another player's card cannot be changed, and drawn numbers are never marked automatically. Verify `manage.py test bingo` passes.
- [x] 5.3 Implement `POST /bingo/r/<code>/claim/` (`{prize}`): check it with `rules` against the stored marks and drawn balls. A valid first claim starts the 10 s pause, and later valid claims during the pause are added as winners. Invalid or refused claims return a Spanish message only to that player. Add tests for every scenario in *Claiming línea*, *Claiming bingo*, *Invalid claims* and *Shared prizes* (two winners in one pause, refused after the pause). Verify `manage.py test bingo` passes.
- [x] 5.4 Implement `POST /bingo/r/<code>/continue/` (host only, ends the pause immediately) and `POST /bingo/r/<code>/auto/` (host only, interval one of 5/8/10/15/20 s or off, saved on `Room`). Add tests: continue ends the pause and moves the stage on; the bingo pause ending finishes the game; an invalid interval is refused; the setting survives a reload of the host screen. Verify `manage.py test bingo` passes.
- [x] 5.5 Implement `GET /bingo/r/<code>/state/` (`never_cache`, read-only, settled state): stage, drawn balls, last ball, pause info (prize, winners' nicknames and winning numbers, `pause_remaining_ms`), winners of finished prizes, and the game id. The player view adds their card, marks and a `removed` flag. The host view adds the players, the auto interval and `next_auto_draw_ms`. Add tests: the JSON matches each stage; a poll writes nothing (no change to `last_activity_at` or to sessions); a player view never includes other players' cards. Verify `manage.py test bingo` passes.
- [x] 5.6 Implement `POST /bingo/r/<code>/new-game/` (host only: delete the old game, create a new one in `waiting`, deal fresh cards to every non-removed player) and `POST /bingo/r/<code>/remove/<id>/` (host only: `removed = True`, delete their card and claims, keep the stage as it is).
